# Экспериментальный мост кадров Redot

Это **экспериментальный прототип**, не готовая система автоматической синхронизации. Он включает локальный мост, MCP-адаптер, аддон для нативного редактора и ручной обмен снимками проекта между настольным и Web-редактором. Кадры игрового viewport и команды Play/Stop передаются локально; сервер хранит только последний кадр. Страница может сохранить кадр и записать до 60 секунд покадрового предпросмотра в WebM без звука. Полноценные видеострим и автоматическая синхронизация файлов не реализованы.

## Безопасность и ограничения

- Сервер намеренно слушает только `127.0.0.1` и работает без TLS. **Не публикуйте его напрямую в интернет.** Для удалённой работы понадобится отдельно спроектированный защищённый сервер, HTTPS/WSS, авторизация и разграничение доступа.
- Каждый HTTP-запрос к кадру требует случайный секрет. Не отправляйте секрет в чат, не записывайте его в репозиторий и не вставляйте в общие файлы конфигурации. На общей машине localhost тоже доступен другим локальным процессам.
- Нативный аддон активируется только после установки, ручного добавления автозагрузки и запуска редактора с `REDOT_BRIDGE_ENABLED=1` и секретом. При запущенной игре кадры отправляются автоматически примерно два раза в секунду; это может снижать производительность. Остановите игру или удалите автозагрузку, чтобы прекратить захват. После остановки последний кадр остаётся в памяти сервера до вызова MCP `delete_game_screenshot`, HTTP DELETE или остановки сервера. Если публикация продолжается, новый кадр появится снова.
- MCP `game_screenshot` возвращает **последний полученный** кадр, а не запускает новый захват. Для MCP и страницы принимаются метки `native-game` и `web-game`; кадры без метки (включая демонстрационное поле) не выдаются как игровые. Метку указывает отправитель: она не является криптографическим доказательством содержимого, поэтому доверяйте только своим клиентам с секретом. MCP и страница показывают время с получения именно этого кадра мостом; после пяти секунд страница предупреждает, что кадр может устареть. Это не время съёмки: отправитель мог передать уже устаревшее изображение. Со старым мостом возраст будет неизвестен. В общем хранилище только один кадр, и другой источник может его заменить. Используйте по одному источнику за раз. Это серия снимков, не real-time видео.
- В [CI](https://github.com/DadyToyBear/game_ai/actions/runs/44911537344) Web RC2 в Chromium с программным WebGL установил и открыл тестовый проект с вложенными папками; исходная папка не изменилась. Исходный RC2 не закрывал игру по `EditorInterface.stop_playing_scene()`. После патча [проверка сборки](https://github.com/DadyToyBear/game_ai/actions/runs/44936393121) прошла: тестовый плагин вызвал Play/Stop в настоящем Web-редакторе, сцена отрисовалась, MCP получил и удалил игровой кадр. Это не проверка физических нажатий, пользовательских проектов или реального GPU. `canvas.toBlob` для других браузеров и рендереров может дать чёрный/устаревший кадр или ошибку. Оверлей — экспериментальный JS в оболочке, **не встроенный EditorPlugin**.
- На Linux в [автоматическом тесте](https://github.com/DadyToyBear/game_ai/actions/runs/44908119109) запущен настоящий нативный Redot RC2 standard с тестовым проектом: MCP и браузер по очереди запускают и останавливают игру, а кадр игрового viewport проверяется по пикселям и удаляется. Это виртуальный дисплей Xvfb с программным OpenGL, не проверка Mono/C#, пользовательского проекта, Windows или GPU. На Android 15 эмуляторе с ARM64 translation отдельно [проверены](https://github.com/DadyToyBear/game_ai/actions/runs/44924168110) Android-редактор, adb reverse, MCP Play/Stop и игровой JPEG; тестовые обработчики подключения и согласия вызваны программно. Физический телефон и пользовательские диалоги не проверены. Минимизация окна, headless-режим или особенности рендерера могут препятствовать захвату.
- В локальном режиме браузер, мост и редактор должны работать на одной машине (Android — через `adb reverse`); агент в облачной песочнице не может автоматически подключиться к localhost пользователя. Отдельный экспериментальный HTTPS relay требует собственного сервера и настройки MCP-клиента; автоматическая синхронизация проектов не реализована.

## Тест на одной машине

Нужен Python 3.9+. В терминале (Linux/macOS):

```bash
export REDOT_BRIDGE_TOKEN="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"
# Скопируйте выведенный секрет только локально, не в чат:
printf '%s\n' "$REDOT_BRIDGE_TOKEN"
python3 redot-bridge/bridge.py serve
```

Windows PowerShell:

```powershell
$env:REDOT_BRIDGE_TOKEN = python -c "import secrets; print(secrets.token_hex(32))"
# Скопируйте значение только локально, не в чат:
$env:REDOT_BRIDGE_TOKEN
python redot-bridge/bridge.py serve
```

Откройте `http://127.0.0.1:8765/`, введите секрет и включите кадры. Это демонстрационный canvas, не игра Redot: снимки имеют метку `unspecified` и намеренно отклоняются инструментом `game_screenshot` и страницей просмотра игры. Доступность кадра можно проверить через `game_status` или авторизованный `GET /api/frame`. Останавливается кнопкой на странице. Остановка сервера — Ctrl+C.

## Нативный Redot: установка аддона (эксперимент)

1. Скопируйте папку `addons/redot_local_bridge` из этого архива/папки в `addons/redot_local_bridge` вашего **проекта** Redot. Не перезаписывайте одноимённый существующий аддон. Работайте на резервной копии проекта.
2. В редакторе откройте Project → Project Settings → Plugins и включите **Redot Local Game Bridge**.
3. Там же в Project Settings → Globals → Autoload (или вкладка Autoload в зависимости от версии) вручную добавьте `res://addons/redot_local_bridge/game_bridge.gd` под новым именем, например `RedotLocalBridgeGame`. Это изменит настройки проекта. Плагин не добавляет и не удаляет автозагрузку автоматически. Перед распространением/релизом удалите автозагрузку и отключите плагин.
4. Полностью закройте редактор. В PowerShell перейдите в папку, содержащую `bridge.py` и `web` (из распакованного комплекта). Создайте временный секрет и запустите Redot из этого же окна, чтобы редактор и его дочерняя игра унаследовали переменные среды:

   ```powershell
   $env:REDOT_BRIDGE_ENABLED = '1'
   $env:REDOT_BRIDGE_TOKEN = python -c "import secrets; print(secrets.token_hex(32))"
   # Скопируйте вывод только локально, никогда не отправляйте в чат:
   $env:REDOT_BRIDGE_TOKEN
   Start-Process -FilePath 'C:\\путь\\к\\Redot.exe'
   python bridge.py serve
   ```

   Укажите реальный путь к своему EXE. Выберите свой проект в открывшемся Redot. Сервер занимает терминал; для остановки нажмите Ctrl+C. Бинарный установщик Redot в этот комплект не входит. Секрет действует до закрытия сервера; запуск из обычного ярлыка или повторно открытый уже запущенный редактор может не унаследовать переменные.
5. Откройте **http://127.0.0.1:8765/native.html** на этой же машине, введите секрет и нажмите «Подключить». После того как аддон начнёт отправлять heartbeat, можно нажать Play/Stop на странице или в редакторе. Игра должна быть запущена для появления кадров. Кнопка «Скачать кадр» сохраняет последний кадр на компьютер, а WebM записывает покадровый просмотр, не окно редактора и не рабочий стол.
6. Если статус не меняется: проверьте, что редактор закрыли и запустили именно из PowerShell с переменными, плагин включён, автозагрузка добавлена, а консоль сервера работает на порту 8765. При чёрном экране или отсутствии кадров не сворачивайте игру, проверьте рендерер и сообщения Output/Debugger.

Play/Stop управляет основной сценой редактора. Это действие меняет состояние проекта/игры и доступно всем клиентам, знающим секрет. Команда в очереди не гарантирует, что игра стартовала: проверяйте status и ошибки редактора. Если получение состояния или кадра зависнет, страница через 10 секунд очистит изображение и попробует снова; отключение отменяет текущий запрос. Код работает только с одиночным локальным редактором и не выполняет удалённое подключение к Arena.

## Экспериментальный relay по HTTPS

Для Android и MCP добавлен одиночный relay для собственного сервера: [инструкция, ограничения и требования безопасности](relay-deploy/README.md). Он не развёрнут автоматически, не подключает Arena и пока не испытан на Android. Локальный `serve` остаётся только на localhost; не публикуйте его напрямую.

## Игра и существующий мультиагентский дашборд рядом

Откройте `http://127.0.0.1:8765/workspace.html` на машине локального моста. Слева находится обычная страница просмотра игры; секрет вводится **только там**. Справа можно явно ввести HTTPS-адрес доверенного существующего дашборда и открыть его во встроенной панели или отдельной вкладке. Ссылка может сама быть секретом доступа: страница очищает поле после открытия, не сохраняет адрес и не отправляет секрет моста в дашборд. Закрытие панели не отменяет удалённые cookie и не закрывает отдельно открытую вкладку.

Дашборд исполняет свой существующий код и обращается к своей шаре независимо. Не открывайте недоверенную страницу и не используйте публичную writable-шару: подмена заданий может управлять старым мостом. Для HTTP допускается только отдельный loopback-сервер, причём HTTPS-страница не встраивает HTTP. Удалённый сервер может запрещать iframe заголовками или cookies/сертификатом; тогда используйте кнопку отдельной вкладки. При отключении COEP для этой страницы сохранена кросс-доменная изоляция Web-редактора; это не инструмент синхронизации и не включение старых WebFTP-команд в новый мост. На HTTPS relay эта страница доступна как `/workspace.html`, но проектов и файлов на relay нет.

## Общий MCP: мультиагентский чат и редактор

Исходный чатовый MCP проекта `redot-mcp-multiagent-bridge` версии `858749552a097363d21b0f0cfa218388fb352e00` включён в сборки рядом с `multiagent_mcp.py`. Этот адаптер предоставляет в **одном MCP stdio** прежние `chat_*` и наши инструменты редактора (`game_*`, снимки, журналы, проекты). Например, из папки моста после запуска локального `bridge.py serve`:

```bash
# Задайте в среде свои REDOT_BRIDGE_TOKEN и WEBFTP_SHARE;
# не записывайте их значения в общий конфиг и не отправляйте в чат.
python3 multiagent_mcp.py
```

В `opencode.multiagent.example.json` приведён пример настройки из корня объединённого дерева; путь к Python и скрипту, а также подстановка переменных зависят от клиента и расположения файлов. Это пример, а не автоматически установленное подключение.

`WEBFTP_SHARE` должен быть HTTPS-адресом доверенной шары; HTTP разрешён только на loopback для локальных тестов. Общий MCP отклоняет HTTP-перенаправления и ограничивает размер ответа чата до 1 МиБ, но это не гарантирует безопасность сервера или разграничение прав. **Не используйте публичную writable-шару**: знание ссылки может позволить подменить старые команды и прочитать результаты. Исходный `chat_assign` по-прежнему пишет задачи в старую шару и может управлять старым WebFTP/WebSocket-мостом; он не вызывает наши `game_play`/`game_stop`. Новые подписанные команды ниже — отдельный экспериментальный протокол, не замена старого. Прямые `game_play` и `game_stop` действуют на подключённый к нашему мосту нативный или Android-редактор; Web-редактор управляется отдельно. Совместимость проверена на локальном имитаторе WebFTP, а не с вашей работающей шарой.

### Экспериментальные подписанные задания через WebFTP

Отдельный worker может читать только `redot-secure-task-<id>.json` и писать подписанный `redot-secure-result-<id>.json`, передавая ограниченный набор команд нашему мосту. Старые `task-*.json`, `chat_assign`, dashboard и существующий worker не перехватываются и автоматически с этим протоколом не совместимы. Форматы list/GET/PUT взяты из открытого протокола WebFTP, но фактический WebFTP, авторизация и клиент Arena не проверены. Файловый импорт/экспорт не поддерживается этим транспортом. HTTPS обязателен вне loopback, редиректы запрещены.

На машине с нашим запущенным мостом и подключённым редактором создайте **отдельный** криптографически случайный `REDOT_TASK_SECRET` (например, `python3 -c 'import secrets; print(secrets.token_hex(32))'`); не используйте токен моста и не публикуйте секрет. В защищённом окружении задайте `REDOT_BRIDGE_TOKEN`, `REDOT_TASK_SECRET`, `WEBFTP_SHARE`; опциональный `WEBFTP_BEARER` передаётся только подписанному транспорту как HTTP Bearer и не добавляется к исходному чат-клиенту. Настройте доступ к шаре и её совместимость с Bearer отдельно. Из папки `redot-bridge` запустите:

```sh
python3 task_transport.py worker --state /path/to/private/persistent/state.sqlite3
```

Папка состояния должна уже существовать и быть доступна только доверенному пользователю; под Windows аналогично используйте `python` и защищённую локальную папку. Сохраните эту SQLite-базу при перезапусках: claim записывается до исполнения. Используйте **одного worker на одну шару и постоянную базу**; независимые базы могут выполнить задание дважды. `--url` позволяет использовать отдельно настроенный HTTPS relay вместо localhost. Эти процессы не запускаются автоматически.

Для общего MCP задайте те же `REDOT_TASK_SECRET` и `WEBFTP_SHARE` (и при необходимости `WEBFTP_BEARER`) в окружении MCP-процесса. Появятся инструменты `webftp_task_submit` и `webftp_task_result`: submit принимает `method` (`game_status`, `game_play`, `game_stop`, `delete_game_screenshot`, `delete_logs`, `game_screenshot`, `read_logs`) и возвращает ID; result принимает этот ID. Для диагностики доступны `python3 task_transport.py send game_status` и `python3 task_transport.py result ID`. Задание действительно 120 секунд, требуется синхронизация часов. Play/Stop лишь ставят команду в очередь моста; проверяйте состояние отдельно.

HMAC защищает целостность и подлинность, **не шифрует** содержимое шары; все её читатели могут видеть файлы, а владелец секрета управляет разрешёнными действиями. Снимки и логи не отправляются без явного `worker --allow-sensitive`; результаты могут сохраняться на сервере и после `delete_game_screenshot`/`delete_logs` — удаление очищает только мост, не WebFTP. Удаляйте файлы на защищённой шаре согласно её политике. Временная ошибка, сбой после claim или отказ загрузки результата может потерять результат; отсутствие результата не доказывает, что действие не выполнялось. Повтор с новым ID может повторно выполнить действие. Список ограничен 10 000 файлами/2 МиБ; старые задания и результаты автоматически не удаляются, ненадёжный сервер может блокировать или задерживать обработку. Не используйте подписанный транспорт как защиту старого небезопасного worker.

## MCP-адаптер

Адаптер связывается с сервером на localhost. Запускайте его в процессе MCP-клиента с той же переменной `REDOT_BRIDGE_TOKEN`:

```bash
python3 redot-bridge/bridge.py mcp
```

Он использует JSON-RPC по stdio (MCP protocol `2025-03-26`) и объявляет `game_screenshot`, `delete_game_screenshot`, `game_play`, `game_stop`, `game_status`, `read_logs`, `delete_logs`, `project_status`, `project_snapshot_export`, `project_snapshot_import`. Журнал Android передаётся только при отдельном согласии, может содержать приватные данные, ограничен и не гарантирует доставку; очистка не останавливает новые записи. Play/Stop ставят команду в очередь; `game_status` показывает последнее состояние редактора, а не гарантию исполнения. Эти команды Play/Stop относятся к **нативному** редактору, не к Web-редактору. Инструменты снимков проекта доступны, только если сервер запущен с `--project-dir`; MCP экспортирует ZIP как встроенный ресурс и импортирует base64 ZIP размером не более 8 МиБ. Импорт всегда создаёт новую соседнюю папку и не изменяет исходник. Обмен с Web-редактором остаётся ручным: через Preload ZIP и Download Project Source.

Конкретный способ передачи переменной окружения зависит от MCP-клиента. Не сохраняйте секрет в общедоступных конфигурациях. Доступ MCP-клиента к локальной команде или к localhost должен существовать отдельно; данный репозиторий не подключает MCP автоматически к Arena.

## Объединить с готовым Web-редактором и обмениваться проектом

Workflow **Assemble Redot Web Editor with Local Bridge** автоматически упаковывает актуальный мост; в `BUILD-PROVENANCE.txt` указаны исходный запуск и ревизии. Если совместимый исходный артефакт истёк, workflow заново собирает редактор. Следующие шаги позволяют также собрать комплект вручную.

1. Скачайте и распакуйте успешный артефакт `redot-26.3-rc2-web-editor` со [страницы сборки](https://github.com/DadyToyBear/game_ai/actions/runs/44878548484#artifacts). Он изначально не содержит мост.
2. В отдельную папку распакуйте комплект моста, содержащий `make_bundle.py`. Запустите, подставив свои пути:

   ```powershell
   python 'C:\\путь\\к\\мосту\\make_bundle.py' 'C:\\путь\\к\\распакованному-редактору'
   ```

   Скрипт добавит в распакованный редактор папку `redot-bridge` и инструкцию `BRIDGE-START.md`. Он не изменяет файлы самого редактора и не перезаписывает существующий мост. Упаковка настоящего Web-артефакта прошла в GitHub Actions; работа всех функций внутри комплекта отдельно не проверена.
3. Перейдите в папку редактора и создайте временный секрет, как в разделе про нативный редактор. Запустите мост:

   ```powershell
   python redot-bridge/bridge.py serve --editor-dir . --project-dir 'C:\\путь\\к\\проекту'
   ```

   `--project-dir` должен содержать `project.godot`. Он разрешает читать все файлы проекта по защищённому локальному запросу. Не запускайте его с папкой, которую не хотите экспортировать. Сервер доступен только на этом компьютере.
4. Откройте `http://127.0.0.1:8765/sync.html`. Экспорт вручную создаёт ZIP, который можно выбрать в Web-редакторе через Preload project ZIP. После работы в Web-редакторе сохраните проект через **Project → Tools → Download Project Source**, выберите ZIP в `sync.html` и импортируйте в **новую соседнюю папку**. Исходный проект не изменится — откройте и сравните копию перед переносом изменений.

Ограничения: это не live sync и не слияние изменений. Браузерный IndexedDB не отслеживается мостом. Сохраняйте работу и не меняйте проект во время экспорта: мост проверяет изменения отдельных файлов, но не гарантирует атомарный снимок всего проекта. Выбор экспорта передаёт все файлы проекта, кроме каталогов `.git` и `.godot`, включая возможные приватные данные. Символьные ссылки и специальные файлы запрещены. Лимиты: 128 МиБ ZIP, 256 МиБ распакованных данных, 64 МиБ на файл и 10 000 записей. MCP ограничен 8 МиБ сжатых данных. Не используйте обмен с недоверенными проектами, не публикуйте сервер в интернете.

## Папки и подключённые сетевые диски

В панели Web-редактора и на `/project-open.html` используется один и тот же раздел **«Папки и подключённые сетевые диски на машине моста»**. Запустите мост на компьютере, на котором доступна папка проекта. Сначала подключите сетевой ресурс средствами ОС (например, Windows `Z:\\Game` или `\\\\server\\share\\Game`; Linux `/mnt/share/Game`). В разделе введите секрет моста и абсолютный путь к папке с `project.godot`, затем нажмите «Добавить папку». Кнопка подготовки создаёт ZIP через существующий механизм снимков: в Web это preload, на странице для Android — скачивание для последующего импорта. Android через USB может открыть страницу на `http://127.0.0.1:8765/project-open.html` после `adb reverse tcp:8765 tcp:8765`. Путь всегда относится к компьютеру, где запущен мост, **не к телефону**. Для работы непосредственно с папкой телефона используйте Import в Android-редакторе, если ОС предоставляет к ней доступ.

Список общий для обоих интерфейсов и хранится только в памяти моста; при перезапуске очищается. Указанный при старте `--project-dir` добавляется в него автоматически. Повторное добавление того же разрешённого пути или доступного ОС алиаса не создаёт вторую запись; сетевые подключения к одному ресурсу через разные серверы/подключения ОС могут иметь разные идентификаторы и не всегда распознаются. Удаление из списка не удаляет файлы. Если папка отключена или заменена, подготовка завершится ошибкой; при замене удалите запись и добавьте снова. В [CI](https://github.com/DadyToyBear/game_ai/actions/runs/44910139696) проверено чтение тестового SMB/CIFS-ресурса, подключённого на той же Linux-машине в режиме read-only; внешний сетевой сервер, Windows и Android ещё не проверены.

Это **не монтирование SMB/NFS, не прямая запись в папку и не синхронизация**. Для Web/Android создаётся отдельная копия проекта; защита от повторной записи в списке не устраняет эти копии. Секрет моста теперь даёт клиенту право добавлять любую доступную его процессу папку и читать её снимки: сообщайте его только доверенным клиентам и не публикуйте localhost-сервер. Relay этот список не предоставляет. Не вводите сетевые пароли в пути; авторизацию сетевого ресурса выполняет ОС. Для снимков действуют прежние ограничения, исключения и предупреждения о конфиденциальных файлах.

## Открыть копию папки или облачного ZIP

На странице Web-редактора, открытой через мост (`/editor/godot.editor.html`), перед запуском появилась секция **«Открыть копию проекта»**. Можно выбрать локальную корневую папку с `project.godot` либо указать прямую HTTPS-ссылку на ZIP. После подготовки нажмите **Start Redot editor**: менеджер проектов автоматически предложит **Install Project: Preload**. Проверьте имя и новую папку назначения, затем нажмите Install. Редактор меняет `config/name` в импортированной копии на имя из окна (по умолчанию `Preload`), поэтому при необходимости укажите исходное имя вручную. Исходная папка не подключается напрямую: редактор работает с копией в хранилище браузера. Встроенный сервер `serve.py` на порту 8060 эту дополнительную панель не подмешивает; используйте `bridge.py serve --editor-dir ...`.

Для Android и других устройств предусмотрена страница `/project-open.html`: она подготавливает и скачивает ZIP; затем его нужно импортировать в менеджере проектов Android Redot. Сам менеджер также позволяет выбрать локальный `project.godot` или папку напрямую, без этой страницы. Через USB-режим с `adb reverse tcp:8765 tcp:8765` адрес страницы на телефоне — `http://127.0.0.1:8765/project-open.html`. Это не автоматически открытый проект и не облачное подключение к устройству; Android ещё не проверен.

Выбор папки зависит от поддержки `webkitdirectory` браузером и предоставленного пользователем доступа. В ZIP локальной папки попадают все файлы, кроме `.git` и `.godot`, в том числе конфиденциальные. Сохраните проект перед копированием: снимок не атомарный. Ограничения: 10 000 файлов, 64 МиБ на файл и 128 МиБ на ZIP; папка без `project.godot` отклоняется. Облачная ссылка должна непосредственно отдавать ZIP и разрешать CORS; перенаправления, cookie-авторизация и URL с пользовательскими данными не поддерживаются. Запрос выполняет браузер, не сервер моста; ссылка не сохраняется специально, но подписанная ссылка сама может содержать секрет. HTTPS обязателен, кроме HTTP на localhost. Для Web, открытого по HTTPS, браузер может блокировать даже локальный HTTP. Облачный ZIP проверяется только по сигнатуре, его содержимое и безопасность не проверяются — импортируйте **только доверенные архивы**. Обе операции создают копию, не обеспечивают двустороннюю синхронизацию или обновление исходной папки.

## Эксперимент с Web-редактором

Когда Web-редактор Redot **успешно собран**, распакуйте артефакт и запустите мост, указав папку с `godot.editor.html`:

```bash
python3 redot-bridge/bridge.py serve --editor-dir /path/to/unpacked-editor
```

В Windows, например: `python redot-bridge/bridge.py serve --editor-dir C:\\redot-web`.

Откройте `http://127.0.0.1:8765/editor/godot.editor.html`. Сервер подмешивает в HTML небольшую панель «Мост: кадры игры» и добавляет заголовки COOP/COEP. Импортируйте проект, запустите игру, введите секрет в панель и включите передачу. Панель пытается захватить только `#game-canvas`, не canvas редактора. Если игра закрыта или вкладка игры скрыта, передача ждёт. При зависании захвата или отправки панель повторяет попытку через 10 секунд; остановка отменяет незавершённый запрос, но не может гарантировать отмену кадра, который сервер уже успел принять. Проверьте возвращённое изображение: успешный HTTP-ответ сам по себе не доказывает, что WebGL-кадр корректен.

```bash
python3 -m unittest discover -s redot-bridge/tests -v
node --check redot-bridge/web/capture.js
node --check redot-bridge/web/redot-overlay.js
node redot-bridge/tests/test_capture.js
node redot-bridge/tests/test_native.js
node redot-bridge/tests/test_sync_page.js
```

Тесты проверяют локальные HTTP-авторизацию, кадр, удаление, MCP stdio и оболочку через синтетические данные; они не проверяют Redot или реальный браузер.
