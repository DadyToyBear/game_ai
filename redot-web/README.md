# Redot 26.3 RC2 — экспериментальный Web-редактор

Сборка из исходников Redot `80d31f765b0ead5551c277704e52bb51c515db1f` (тег `redot-26.3-rc.2`), Emscripten 4.0.11, `target=editor`, `threads=yes`. Это не Mono-сборка и не гарантия совместимости всех аддонов. Сборка редактора и совместимость с отдельными плагинами нуждаются в проверке в браузере.

## Скачать и запустить

1. В GitHub откройте Actions → **Build Redot 26.3 RC2 Web Editor** → успешный запуск → Artifacts → **redot-26.3-rc2-web-editor**. Артефакт хранится 14 дней. Распакуйте его в отдельную папку.
2. Установите Python 3, если он не установлен. В терминале внутри распакованной папки запустите:

   ```bash
   python3 serve.py
   ```

   В Windows можно использовать `py serve.py`. Откройте `http://localhost:8060/godot.editor.html` на той же машине. Для остановки нажмите Ctrl+C. Сервер предназначен только для локальной проверки и слушает исключительно localhost.
3. Нужен современный браузер с WebGL 2 и SharedArrayBuffer. Сервер задаёт COOP/COEP для потоков. Для публикации в сети нужны HTTPS, корректные заголовки и отдельная настройка безопасности; `file://` не подходит.

## Проверить GDScript-аддон

На стартовой странице выберите `plugin-smoke-test.zip` в **Preload project ZIP** и запустите редактор. Импортируйте/откройте тестовый проект, затем включите **Web Smoke Test** в Project → Project Settings → Plugins. Должен появиться док с текстом `GDScript editor plugin is running.` и сообщение в Output. Отключите плагин и убедитесь, что док исчезает. Это ручная проверка одного простого плагина, а не тест всех аддонов или MCP.

Данные редактора хранятся в браузере, а не в папке с сервером. Экспортируйте резервные копии проекта через Project → Tools → Download Project Source; очистка данных сайта может их удалить.

Плагины, требующие запуска внешних процессов, локальных TCP-серверов, C#/Mono или нативных библиотек, могут не работать в браузере без серьёзной адаптации. Для MCP-аддона необходима отдельная проверка транспортного протокола и ограничений браузера.

## Повторная сборка

Workflow запускается при изменениях сборочных файлов в ветке `arena/b84b9c4f-game-ai`. Он также содержит `workflow_dispatch`, но GitHub позволяет ручной запуск только когда workflow существует в default branch. В текущей ветке повторно запустить существующий workflow можно кнопкой **Re-run jobs** в интерфейсе GitHub.
