# Быстрый старт: 5 минут до первого переноса

Короткая инструкция без теории. Полная — в `README.md`.

---

## 1. Что нужно

| Что | Зачем | Проверка |
|---|---|---|
| **Redot 26.x** (или Godot 4.5) | целевой движок | окно редактора открывается |
| **Node.js 18+** | сборщик разбирает HTML/CSS/JS | `node --version` → `v18…` и выше |
| каталог веб-игры | откуда переносим | внутри есть `viewer/`, `src/`, `assets/` |

Node обязателен только для сборки. Готовый проект в Redot открывается без Node.

---

## 2. Установка плагина

**Вариант A — архив (проще).** Скачайте `webport-addon.zip` и распакуйте в корень
своего проекта Redot так, чтобы получилось:

```
ваш_проект/
├── project.godot
└── addons/
    └── webport/          ← plugin.cfg, plugin.gd, core/, tools/, …
```

**Вариант B — из репозитория.**

```bash
cp -r addons/webport  /path/to/redot-project/addons/
```

**Включение.** В Redot: `Project → Project Settings → Plugins` → напротив
**WebPort** нажмите `Enable`. Внизу редактора появится панель **WebPort**
(или `Проект → Сервис → WebPort: открыть панель переноса`).

Если плагин не включается — проверьте консоль: обычно это старая версия
движка (нужен 26.x / 4.5) или не найден Node.

---

## 3. Первый перенос

1. **Панель WebPort** → строка «Веб-игра (HTML/JS)» → кнопка `...` → выберите
   каталог веб-версии.
2. Строка «Проект Redot (куда)» → `...` → выберите каталог проекта
   (можно пустой: сборщик создаст `project.godot`, сцены и скрипты).
3. Для первой проверки **снимите галочку** «копировать ассеты» — сборка
   станет в разы быстрее (секунды вместо минуты).
4. Нажмите **Собрать проект**. В логе появится:

```
Экранов: 3, модулей: 5, GDScript: 648 строк
Ассетов: 0 (0 МБ), данных: 384
Замечаний: 48 (ручных: 16), предупреждений: 64
Линтер GDScript: проверено 5, ошибок 0
```

5. Кнопка **Отчёт** открывает `webport/report.json`; **Проверка** — локальную
   страницу со структурой сцен и предпросмотром.

Всё то же из терминала:

```bash
node addons/webport/tools/build_project.mjs \
  --source /path/to/web-game \
  --out    /path/to/redot-project \
  --name   "Корона и знамя"
```

## 4. Что получится в проекте

```
ваш_проект/
├── project.godot                  создан/обновлён
├── scenes/
│   ├── Game.tscn                  главная сцена из viewer/game.html

│   └── SquadDemo.tscn

├── webport/

│   ├── src/battle_contract.gd

│   ├── REPORT.md                  отчёт для человека

```

Откройте проект в Redot обычным способом — сцены уже в файловой системе.

## 5. Как читать отчёт

`webport/REPORT.md` делит всё на три категории:

| Раздел | Значение | Что делать |
|---|---|---|
| **Итог** | сколько экранов/модулей/строк | оценка объёма работ |
| **Ошибок линтера GDScript** | должно быть **0** | если больше — пришлите номер строки, это баг конвертера |
| **Что требует внимания** | места с номером строки JS | ручная работа: `innerHTML`, `document.*`, `fetch`, `await`, `class` |
| **Предупреждения** | перенесено, но проверьте | `Set`/`Map`, `try/catch`, вынесенные лямбды |

Правило: **сначала добивайтесь нуля ошибок линтера, потом беритесь за замечания.**
Ошибка линтера означает, что файл вообще не загрузится в движке; замечание — что
код загрузится, но конкретное место нужно переписать руками.

## 6. Подключение перенесённой логики к сцене

Модель боя — обычный класс с `static func`. Подключается так:

```gdscript
extends Node

const Battle := preload("res://webport/src/battle_simulation.gd")

var state: Dictionary

func _ready() -> void:
	state = Battle.createBattle({
		"seed": 42,
		"map": {"width": 9, "height": 5},
		"attacker": {"regiments": [{"id": "a1", "class": "swords", "count": 120}]},
		"defender": {"regiments": [{"id": "d1", "class": "archers", "count": 80}]},
	})
	state["paused"] = false

func _process(_delta: float) -> void:
	if state.get("result") == null:
		state = Battle.stepBattle(state)
```

Обращение к элементам интерфейса по их html-id:

```gdscript
# таблица id → узел подхватывается автозагрузкой WebportLinks
WebportLinks.set_prop("resourceBar", "visible", true)
WebportLinks.set_prop("realmName", "text", "Дом Кэрна")
print(WebportLinks.ui("endTurn"))
```

Автозагрузка `WebportLinks` прописывается в `project.godot` автоматически при сборке.

## 7. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Кнопка «Собрать» неактивна | Node не найден в `PATH` | установите Node 18+, перезапустите Redot |
| `не найден tools/build_project.mjs` | скопирован только `plugin.gd` | копируйте каталог `addons/webport/` целиком |
| Сцена пустая / мало узлов | интерфейс строится из JS (`innerHTML`) | это ожидаемо: см. раздел «Что требует внимания» в отчёте |
| Ассеты не видны в сцене | сборка была с `--no-copy-assets` | пересоберите с галочкой «копировать ассеты» |
| Ошибки GDScript при открытии | файлы правились вручную после сборки | правьте JS-исходник и пересоберите: заголовок `.gd` предупреждает об этом |
| `WebportLinks` не найден | проект не собран целиком | проверьте раздел `[autoload]` в `project.godot` |

## 8. Полезные команды

```bash
# тесты самого плагина (35 проверок, движок не нужен)
node addons/webport/tests/run_tests.mjs

# только HTML-экран игры; модули и JSON остаются общими
node addons/webport/tools/build_project.mjs --source ../web --out ../redot --only viewer/game.html --no-copy-assets

# собрать и сразу открыть страницу проверки
node addons/webport/tools/build_project.mjs --source ../web --out ../redot --serve

# проверить синтаксис GDScript (если стоит gdtoolkit: pip install gdtoolkit)
gdparse ../redot/webport/src/*.gd ../redot/scripts/*.gd

# упаковать плагин в архив
node addons/webport/tools/pack_zip.mjs --out dist/webport-addon.zip
```

## 9. Порядок работы, который экономит время

1. Собрать **без ассетов** и посмотреть отчёт (секунды).
2. Довести до нуля ошибок линтера.
3. Открыть сцены в Redot и поправить раскладку (обычно 5–10 правок `size_flags`).
4. Пересобрать **с ассетами**.
5. Подключить модель (`webport/src/*.gd`) к сценам и заменить DOM-заглушки
   на реальные узлы по таблице `webport/dom_links.json`.
