# Установка WebPort: все способы и проверка

Подробная инструкция по установке и первой проверке. Если нужно «просто
запустить» — откройте `БЫСТРЫЙ_СТАРТ.md`.

---

## 1. Требования

| Компонент | Версия | Обязателен | Проверка |
|---|---|---|---|
| Redot | 26.x (совместим с Godot 4.3+) | да | `redot --version` |
| Node.js | 18 LTS или новее | для сборки | `node --version` |
| Python + gdtoolkit | 3.9+ | опционально (линт GDScript) | `gdparse --version` |

Почему Node: разбор JavaScript без полноценного парсера невозможен, а писать
второй парсер на GDScript — значит поддерживать его вечно. В `vendor/` лежит
acorn (MIT, 8.19.0), он используется только при сборке.

Линтер GDScript нужен, чтобы видеть ошибки синтаксиса до открытия движка:

```bash
pip install gdtoolkit     # даёт команду gdparse
```

Без него сборка работает, но в отчёте будет строка «синтаксис не проверялся»
вместо честного числа ошибок.

## 2. Три способа установки

### 2.1. Из архива (рекомендуется)

1. Скачайте `webport-addon.zip`:
   - из репозитория: `dist/webport-addon.zip`;
   - прямая ссылка: `https://raw.githubusercontent.com/DadyToyBear/game_ai/arena/884c3d81-game-ai/dist/webport-addon.zip`
2. Распакуйте **в корень проекта Redot** (не в `addons/`, а в корень — внутри
   архива уже есть `addons/webport/…`).

```bash
unzip webport-addon.zip -d /path/to/redot-project
```

Должно получиться:

```
/path/to/redot-project/
├── project.godot
└── addons/webport/
    ├── plugin.cfg
    ├── plugin.gd
    ├── gdscript/       (панель и запуск сборщика)
    ├── core/           (js_to_gd, html_to_scene, …)
    ├── runtime/        (WebportRuntime, WebportLinks)
    ├── tools/          (build_project.mjs, serve.mjs, pack_zip.mjs)
    ├── tests/
    └── vendor/acorn.mjs
```

3. Redot → `Project → Project Settings → Plugins` → **WebPort** → `Enable`.

### 2.2. Копированием из репозитория

```bash
git clone https://github.com/DadyToyBear/game_ai.git
cd game_ai
cp -r addons/webport /path/to/redot-project/addons/
```

Полезно, если хотите править сам плагин: сборка берёт файлы из клона.

### 2.3. Глобально (для всех проектов)

Redot поддерживает каталог плагинов в профиле пользователя:

| ОС | Путь |
|---|---|
| Linux | `~/.local/share/redot/addons/` |
| Windows | `%APPDATA%\Redot\addons\` |
| macOS | `~/Library/Application Support/Redot/addons/` |

```bash
cp -r addons/webport "$HOME/.local/share/redot/addons/"
```

После этого плагин виден в списке плагинов любого проекта. Удобно для тестов,
но для переносимого проекта лучше вариант 2.1: плагин поедет вместе с проектом.

## 3. Проверка установки

### 3.1. Проверка без Redot (30 секунд)

Самый быстрый способ убедиться, что всё на месте:

```bash
cd /path/to/redot-project
node addons/webport/tests/run_tests.mjs
```

Ожидаемый вывод:

```
...
35 проверок пройдено, 0 провалено
```

Если проверки провалились — проблема в окружении (старый Node), а не в вашем проекте.

### 3.2. Проверка в редакторе

1. Включите плагин (см. выше).
2. Внизу появится панель **WebPort**; в её шапке — строка состояния:
   - `Node v20.x — готово к сборке` (зелёным) — всё хорошо;
   - `Node.js не найден в PATH…` (красным) — установите Node и **перезапустите Redot**
     (редактор не подхватывает изменения `PATH` на лету).
3. Кнопка **Собрать проект** должна быть активной.

### 3.3. Проверка на демо-проекте

В репозитории есть готовый пример: веб-игра `examples/webgame_min/` и её
перенос в `demo/webport_min/`.

```bash
# пересобрать демо у себя
node addons/webport/tools/build_project.mjs \
  --source examples/webgame_min \
  --out    /tmp/webport_demo \
  --name   "WebPort demo"

# открыть результат
redot --path /tmp/webport_demo
```

В `/tmp/webport_demo` должно появиться: `project.godot`, `scenes/Index.tscn`,
`scripts/Index.gd`, `webport/src/campaign.gd`, `webport/REPORT.md`.
Отчёт для этого примера: 1 экран, 2 модуля, **0 ручных замечаний**.

## 4. Настройки плагина

`Project → Project Settings → WebPort` (или `General → webport`):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `webport/source_path` | пусто | каталог веб-игры (запоминается между запусками) |
| `webport/out_path` | пусто | каталог проекта Redot для сборки |
| `webport/copy_assets` | `true` | копировать картинки и звук |
| `webport/reload_after_build` | `true` | обновлять файловую систему редактора после сборки |
| `webport/serve_port` | `8123` | порт локальной страницы проверки |

Настройки хранятся в `project.godot` секцией `[webport]` и не содержат
секретов и абсолютных путей, если вы сами их туда не вписали.

---

## 5. Обновление и удаление

**Обновление.** Распакуйте новый архив поверх — файлы плагина заменятся,
настройки проекта (`[webport]` в `project.godot`) останутся.

**Удаление.** Выключите плагин в `Project Settings → Plugins`, затем удалите
`addons/webport/` и (по желанию) сгенерированные каталоги `webport/`, `scenes/`,
`scripts/` — они помечены в своих заголовках как созданные сборщиком.

## 6. Если что-то не работает

| Симптом | Причина | Решение |
|---|---|---|
| Панель WebPort не появилась | плагин не включён или старая версия движка | проверьте `Plugins`, нужен Redot 26.x / Godot 4.3+ |
| `Не найден tools/build_project.mjs` | скопирован только `plugin.gd` | копируйте каталог `addons/webport/` целиком |
| Кнопка «Собрать» серая | Node отсутствует в `PATH` | установите Node 18+, перезапустите Redot |
| Сборка падает с `EACCES`/`EPERM` | нет прав на запись в каталог проекта | выберите другой каталог или исправьте права |
| В отчёте «синтаксис не проверялся» | не установлен gdtoolkit | `pip install gdtoolkit` |
| Сцены не грузятся, ошибка `Parse Error` в `.gd` | файл правили вручную после сборки | правьте JS и пересоберите: `.gd` перезаписывается |
| `WebportLinks` не является автозагрузкой | проект собран не с нуля | проверьте секцию `[autoload]` в `project.godot` |

Для диагностики приложите к сообщению об ошибке `webport/report.json` —
в нём есть версии, список файлов и все замечания с номерами строк.
