# Работа с WebPort: от веб-игры до проекта Redot

Практическое руководство: что делает каждая кнопка, как читать отчёт, как
доводить перенос до играбельного состояния и где проходят границы автоматизации.

---

## 1. Модель переноса

Плагин не «конвертирует игру», он **разбирает её на слои** и переносит каждый
слой тем способом, который в Redot работает:

| Слой веб-игры | Куда попадает | Степень автоматизации |
|---|---|---|
| Разметка и CSS | сцена `.tscn` (дерево узлов, стили, id) | высокая: структура и вид |
| Правила и расчёты (`src/*.mjs`) | `webport/src/*.gd`, те же функции | высокая: синтаксис и семантика |
| Данные (`data/*.json`) | `data/*.json` | полная: файлы копируются |
| Ассеты | `assets/**` | полная: пути не меняются |
| Обновление интерфейса из JS | GDScript-заглушки + таблица id | низкая: пишется руками |

Отсюда главное правило: **чем меньше интерфейс строится из JS, тем полнее перенос.**
Если разметка лежит в HTML, вы получаете готовое дерево узлов. Если она
собирается через `innerHTML`, переносится только контейнер.

---

## 2. Панель WebPort

```
┌─ WebPort — перенос браузерной игры в Redot ───────────────┐
│ Веб-игра (HTML/JS):   [/path/to/web]              [ ... ] │
│ Проект Redot (куда):  [/path/to/redot-project]    [ ... ] │
│ HTML-экраны: [viewer/game.html]                         │
│ [x] копировать ассеты                                     │
│ [ Собрать проект ] [ Отчёт ] [ Проверка ]                 │
│ Node v20.11 — готово к сборке                             │
│ Экранов: 1  Модулей: 3  Строк GDScript: 638               │
│ TODO: 12  Предупреждений: 67  Ошибок линтера: 0           │
│ ┌ лог сборки ──────────────────────────────────────────┐  │
│ │ Экранов: 1, модулей: 3, GDScript: 638 строк          │  │
│ │ Ассетов: 1821 (357.7 МБ), данных: 386                │  │
│ └──────────────────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────┘
```

| Элемент | Что делает |
|---|---|
| **Веб-игра** | каталог, где лежат `viewer/`, `src/`, `data/`, `assets/` |
| **Проект Redot** | куда собирать; выберите каталог вне исходников |
| **HTML-экраны** | пусто — все страницы; `viewer/game.html` — только экран кампании |
| **копировать ассеты** | снятая галочка = быстрая проверка структуры без 358 МБ |
| **Собрать проект** | вызывает Node-сборщик, печатает вывод, обновляет сводку |
| **Отчёт** | открывает `webport/report.json` |
| **Проверка** | поднимает локальную страницу со сценами и предпросмотром |

Пути запоминаются в `project.godot` (`[webport]`), поэтому повторная сборка —
это одно нажатие.

## 3. Страница проверки

Кнопка **Проверка** запускает `tools/serve.mjs` на порту `webport/serve_port`
(по умолчанию 8123) и открывает браузер:

* **слева** — список экранов (страница → сцена) и `report.json`;
* **справа** — дерево узлов сцены: имя, тип, вложенность;
* **Предпросмотр сцены** — HTML-рендер дерева `.tscn` с реальными цветами,
  рамками и размерами из `StyleBoxFlat`.

Предпросмотр не заменяет движок (раскладку контейнеров считает Godot), но
мгновенно показывает три типичные ошибки:

1. узел не создан (элемента нет в дереве);
2. фон/рамка потерялись (нет `SubResource("StyleBoxFlat…")`);
3. размеры неверны (нет `custom_minimum_size`).

## 4. Как читать отчёт

### 4.1. Итог

```
| Показатель | Значение |
| Экранов (HTML → сцена, фильтр `viewer/game.html`) | 1 |
| Статических узлов сцены | 128 |
| JS-модулей → GDScript | 3 |
| Строк GDScript | 638 |
| JSON-данных скопировано | 386 |
| Ассетов скопировано | 1821 (357.7 МБ) |
| TODO / предупреждений | 12 / 67 |
| Динамических HTML-узлов для ручной сцены | 6 |
| Ошибок линтера GDScript | 0 |
```

**Ошибок линтера должно быть 0.** Это не стиль, а работоспособность: файл с
ошибкой парсинга не загрузится, и сцена останется без скрипта.

### 4.2. Три категории замечаний

| Категория | Пример | Как исправлять |
|---|---|---|
| **Ошибка линтера** | `GDScript не компилируется: …` | это баг конвертера; пришлите строку — правка в `core/js_to_gd.mjs` |
| **Требует внимания** | `строка 44: getElementById() — используйте WebportDom` | перенести конкретное место руками |
| **Предупреждение** | `Set → Array (для .has() используется in)` | проверить, что логика та же |

### 4.3. Типовые замечания и что делать

| Замечание | Значение | Действие |
|---|---|---|
| `getElementById()` / `querySelector()` | ищем узел по id | `WebportLinks.ui("id")` |
| `.innerHTML = …` | строим разметку строкой | разметка → в сцену; обновление → `set_prop` |
| `.addEventListener("click")` | обработчик события | сигнал `pressed` в `_ready()` сцены |
| `fetch('/data/x.json')` | загрузка данных | `FileAccess` + `JSON.parse_string` (читается мгновенно) |
| `await` / `.then` | асинхронность | сигналы, `Timer`, `_process` |
| `requestAnimationFrame` | игровой цикл | `_process(delta)` |
| `class Unit {}` | классы JS | сцена + скрипт, либо композиция |
| регулярные выражения | RegEx | `RegEx.new()` + `compile()` |
| `canvas.getContext("2d")` | императивное рисование | `_draw()`, `Node2D`, `Sprite2D` |

### 4.4. Предупреждения, которые не надо бояться

* `Set → Array` — для `.has()` используется `in`, поведение то же;
* `Map → Dictionary` — `get/set` заменены на `Dictionary.get/[] =`;
* `try/catch выполняется всегда` — ветка `catch` вставлена линейно;
* `многострочная лямбда вынесена в метод` — проверьте захват переменных;
* `|| с побочным эффектом` — правая часть вычисляется всегда.

## 5. Типовой цикл работы

### Шаг 1. Структура (секунды)

```bash
node addons/webport/tools/build_project.mjs \
  --source ../game_ai_web --out ../koh_redot --no-copy-assets
```

Смотрите: сколько узлов на экран, сколько замечаний, что с линтером.
Дешёвая итерация — пока не станет 0 ошибок.

### Шаг 2. Модули логики

Откройте `webport/REPORT.md` → раздел «JS → GDScript». У модулей правил
(`battle_simulation`, `battle_contract`) нужно разбирать по каждому TODO и
семантическому предупреждению; нулевой синтаксический lint сам по себе не
подтверждает эквивалентность поведения.

```bash
# быстро пересобрать экран игры без тяжёлых ассетов;
# --only фильтрует HTML-экраны, игровые модули остаются общими
node addons/webport/tools/build_project.mjs --source ../web --out ../redot --only viewer/game.html --no-copy-assets
```

### Шаг 3. Сцены в редакторе

Откройте проект в Redot. Что обычно требует правок:

| Что | Почему | Как |
|---|---|---|
| отступы внутри панелей | CSS `padding` не выражается один в один | `MarginContainer` либо `theme_override_constants/*` |
| растяжение по ширине | `size_flags_horizontal = 3` | выставить у нужных детей |
| шрифты | в CSS семейство, в Godot — `FontFile` | подключить `.ttf` и задать `theme_override_fonts/font` |
| абсолютные позиции | `position:absolute` в CSS | `anchors_preset` / скрипт |

### Шаг 4. Ассеты

Пересоберите без `--no-copy-assets`. Пути уже совпадают с веб-версией
(`/assets/ui/battle/battle_panel.png` → `res://assets/ui/battle/battle_panel.png`),
поэтому ничего переименовывать не нужно.

### Шаг 5. Подключение логики

```gdscript
extends Node

const Battle := preload("res://webport/src/battle_simulation.gd")
const Contract := preload("res://webport/src/battle_contract.gd")

func _ready() -> void:
	# бой считается тем же кодом, что в веб-версии
	var request := Contract.createBattleRequest({
		"seed": 7,
		"scenarioId": "bridge_defense",
		"attacker": {"regiments": [{"id": "a1", "class": "swords", "count": 120}]},
		"defender": {"regiments": [{"id": "d1", "class": "archers", "count": 80}]},
	})
	var result := Contract.resolveBattleRequest(request)
	print("победитель: ", result["winner"], " потери: ", result["casualties"])
```

### Шаг 6. Замена DOM-заглушек

В сгенерированных скриптах экранов остались вызовы вида
`WebportRuntime.set_dom("gold", "textContent", …)`. Они работают «из коробки»
(находят узел по имени и кладут значение), но правильнее подключить типизацию:

```gdscript
# было (сгенерировано)
WebportRuntime.set_dom("realmName", "textContent", state.title)

# стало (руками, с проверкой типа)
@onready var realm_name: Label = WebportLinks.ui("realmName")
...
realm_name.text = state.title
```

## 6. Таблица соответствий (шпаргалка)

### Разметка

| HTML | Redot |
|---|---|
| `div` с фоном | `Panel` + `StyleBoxFlat` |
| `div` без фона | `Control` |
| `display:flex` | `HBoxContainer` / `VBoxContainer` |
| `display:grid` | `GridContainer` + `columns` |
| `button` | `Button` |
| `select` | `OptionButton` |
| `input[type=text]` | `LineEdit` |
| `input[type=checkbox]` | `CheckBox` |
| `img` | `TextureRect` (+ `ExtResource`) |
| `span`, `b`, `small`, `h1…h6` | `Label` |
| `canvas` | `Viewport` (заглушка) |

### Код

| JS | GDScript |
|---|---|
| `a / b` | `WebportRuntime.div(a, b)` — иначе `3/2 == 1` |
| `a \|\| b`, `a && b` | `or`/`and` для условий, `(a if a else b)` для значений |
| `{...obj, k: v}` | `WebportRuntime.merge({}, obj, {"k": v})` |
| `Math.*`, `Object.keys/values/entries` | встроенные функции и `keys/values/entries` |
| `arr.map/filter/some/find/reduce` | `WebportRuntime.*` |
| `arr.sort(cmp)` | `arr.sort_custom(cmp)` |
| `arr.includes(x)` | `x in arr` |
| `dict[k]` / `dict[k] = v` | то же самое |
| `for (const x of arr)` | `for x in arr:` |
| `for (let i = 0; i < n; i++)` | `for i in range(n):` |
| `for (const [k, v] of dict)` | `for k in dict.keys(): var v = dict[k]` |
| `a?.b` | `(a.b if a != null else null)` |
| `x ?? y` | `(x if x != null else y)` |
| `structuredClone(x)` | `x.duplicate(true)` |

## 7. Правила, которые стоит соблюдать в веб-версии

Если вы продолжаете развивать веб-версию и хотите дешёвый перенос:

1. **Разметку — в HTML, а не в строках.** `innerHTML` переживает перенос хуже всего.
2. **Данные — в JSON.** Они переносятся один в один и читаются быстрее.
3. **Правила — в отдельные `.mjs` без DOM.** Такие модули переносятся почти без потерь.
4. **Не смешивайте расчёты и DOM** в одной функции: разделённый код переезжает целиком.
5. **Держите `id` стабильными** — это ключи таблицы `dom_links.json`.

---

## 8. Ограничения (принять заранее)

* Интерфейс, собираемый из JS, переносится **как структура**, а не как поведение.
* `<canvas>` становится узлом-заглушкой: рисование переписывается.
* Классы JS не транслируются.
* Асинхронность (`fetch`, `await`, таймеры) переписывается на сигналы.
* Пиксельная точность CSS недостижима: раскладка в Godot контейнерная.

Это не недостатки плагина, а разница между DOM и деревом сцен. Плагин делает
всё, что можно сделать детерминированно, и честно перечисляет остальное.
