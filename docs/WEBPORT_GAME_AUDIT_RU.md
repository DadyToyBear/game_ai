# Аудит переноса «Короны и знамени» через WebPort

Проверен реальный исходник игры, а не только демонстрационный проект WebPort.

## Повторить сборку

Из корня репозитория:

```bash
node addons/webport/tools/build_project.mjs \
  --source . \
  --out ../crown-and-banner-redot \
  --name "Корона и знамя" \
  --only viewer/game.html
```

`--only` выбирает HTML-экраны, а не отбрасывает общие модули, JSON и ресурсы. Отчёты сохраняются в `webport/REPORT.md` и `webport/report.json` выходного проекта.

## Результат прогона

- 1 экран, HTML → сцена `Game.tscn`, 128 статических узлов.
- 3 ES-модуля → 638 строк GDScript.
- 386 JSON-файлов и 1 821 ассет (357,7 МБ).
- 10 пунктов TODO: 8 CSS-ограничений ширины и 2 места в JS, требующие ручной проверки.
- 67 предупреждений, включая 6 HTML-узлов, которые создаются динамически и должны быть вручную представлены в сцене.
- `gdparse` проверил все 3 сгенерированных GDScript-файла: 0 синтаксических ошибок.

HTML-парсер ранее обрывал встроенный JavaScript на символах `<` (например, в сравнении); из-за этого конвертация главного экрана фактически не доходила до большей части кода. Парсер исправлен и теперь обрабатывает содержимое `<script>` и `<style>` как raw text до соответствующего закрывающего тега. Полный скрипт игры размером около 210 КБ теперь извлекается, экранный GDScript подключается к корневому узлу сцены, а непереносимые динамические элементы перечисляются в отчёте. Это подключение пока даёт основу для ручной доработки, а не готовую логику кампании. Код из `examples/` больше не попадает в конвертацию игровых GDScript-модулей.

## Важные границы результата

Сборка **не является готовой нативной версией игры**. Экран кампании строится из JavaScript через динамический DOM и Canvas; сцена содержит только 128 статических узлов, шесть динамических элементов отмечены для ручного создания, а логика DOM/Canvas и обработчики событий требуют отдельного переноса. Конвертация модулей боевой симуляции создаёт основу GDScript, но отчёт содержит семантические предупреждения — её поведение нужно сверить с исходником.

В среде проверки Redot/Godot не установлен. `gdparse` подтверждает синтаксис файлов, но не проверяет загрузку сцен, ресурсы, сигналы, автозагрузки или игровую эквивалентность в движке. Перед релизом необходимо открыть проект в целевой версии Redot, устранить пункты отчёта, затем пройти игровые сценарии вручную. Архив плагина устанавливает сам WebPort; он не превращает исходную браузерную игру в готовый Redot-проект одним нажатием.
