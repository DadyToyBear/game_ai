# Телефоны, планшеты и сенсорное управление

Эта заметка описывает действующие сенсорные сценарии браузерной игры и настройки проекта, который генерирует WebPort. Она различает HTML-версию и автоматически переносимую Godot-сборку: переносчик создаёт сцену/скрипты и отчёт, но не превращает весь браузерный runtime в готовую нативную игру.

## Браузерная игра (`viewer/game.html`)

### Карта кампании

- Один палец перетаскивает карту; два пальца масштабируют её с сохранением точки под центром жеста.
- Перетаскивание мини-карты переносит камеру.
- Касание дружины выбирает или снимает выбор; касание поселения открывает его совет, если дружина не выбрана.
- Панель державы выдвигается поверх карты в портретной ориентации. Нижняя панель команд прокручивается, кнопки имеют сенсорную высоту не менее 44 px.
- На устройствах с безопасными зонами учитываются `safe-area-inset-*` отступы.

### Тактическое поле

- На узких экранах (ширина viewport до 520 px) поле боя можно прокручивать по горизонтали, вместо того чтобы уменьшать все девять колонок до тесных клеток. В каждой клетке сохраняется минимум 44 px высоты.
- Подсказка над полем напоминает о горизонтальном жесте. Дружину выбирают касанием жетона, затем касаются цели или клетки для приказа.
- Боевые команды на экранах до 820 px остаются у нижнего края окна; панель прокручивается горизонтально, а её позиция сохраняется при обновлении симуляции.
- Свайп по полю и свайп по панели команд относятся к разным областям прокрутки; поле размечено как самостоятельный доступный регион.

## WebPort и Godot 4.3+

WebPort генерирует `project.godot` с совместимостью `4.3`, рендерером GL Compatibility (включая мобильный вариант) и растягиваемым viewport с аспектом `expand`. Для переведённых из mouse/click обработчиков включается эмуляция мыши из касаний; обратная эмуляция касаний из мыши отключена.

Сгенерированный проект — основа для переноса, не доказательство полного нативного порта. Canvas-отрисовка, динамические DOM-состояния и отмеченные `TODO` требуют отдельной реализации/проверки в движке. После сборки откройте проект именно в Godot 4.3 или новее и проверьте целевые портретное/альбомное разрешения и сенсорное устройство.

Пример генерации:

```bash
node addons/webport/tools/build_project.mjs \
  --source . \
  --out ../crown-and-banner-godot \
  --name "Корона и знамя" \
  --only viewer/game.html
```

Не размещайте выходной каталог внутри исходного проекта. Для этого репозитория тесты игры и WebPort запускаются отдельно:

```bash
npm test
node addons/webport/tests/run_tests.mjs
```

DOM smoke-тесты проверяют карту, выбор дружин, сенсорную компоновку поля боя и панель приказов. Они не заменяют ручной визуальный проход в мобильном браузере или проверку экспорта в установленном Godot.
