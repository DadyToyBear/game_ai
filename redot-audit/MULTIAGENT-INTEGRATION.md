# Совместимость с redot-mcp-multiagent-bridge

Основа анализа — открытое дерево репозитория
`DadyToyBear/redot-mcp-multiagent-bridge`, commit
`858749552a097363d21b0f0cfa218388fb352e00`. Его дерево содержит
`multiagent-mcp.py`, `dashboard.html`, протокол чата и документацию; в нём
нет реализации описанного WebSocket/WebFTP `bridge.py`, `mcp_call.py`, самого
редактора или аддона Godot MCP Pro. Согласно документации они находятся в
другом месте работающей установки. Копия файлов `multiagent-upstream/` скачана
из GitHub и сверена с идентификаторами blob указанного дерева. Исходная установка,
доступность удалённой шары и текущие процессы не проверены.

## Что отличается

- Рабочий проект описывает агента, который помещает `task-*.json` в WebFTP и
  получает `result-*.json`; отдельный сервер общается с аддоном по WebSocket.
  В репозитории имеется отдельный MCP чата (пять `chat_*` инструментов).
- `redot-bridge` в этом репозитории — другой протокол: localhost HTTP и MCP
  stdio, heartbeat/очередь Play/Stop, последний игровой кадр, снимки проекта,
  журнал, отдельные native/Android аддоны и экспериментальный HTTPS relay.
- `redot-bridge/multiagent_mcp.py` предоставляет инструменты обоих MCP через
  один stdio клиенту. Дополнительный opt-in `task_transport.py` обрабатывает
  только новые подписанные `redot-secure-task-*`, а не старые `task-*` или
  `chat_assign`. Проверены чат и новый транспорт на локальных имитаторах;
  реальную шару, дашборд, старый worker и Arena мы не подключали.
- Нативный аддон, Android-редактор и Web overlay различны; сборки Web/Android
  standard, не доказаны C# и пользовательские проекты. Двусторонней синхронизации
  и полноценного потокового видео в текущем мосте нет.

## Защита работающей установки

Документация другого проекта описывает публичную WebFTP-шару с правом записи
по HTTP, где используются файлы команд и результатов. Если конфигурация всё
ещё такая, любой получивший адрес может потенциально читать или подменять
задания/результаты, а HTTP не защищает их в сети. Следует закрыть публичную
запись и использовать защищённый канал с авторизацией и ограничением прав,
прежде чем подключать команды управления редактором. Наличие HTTPS только у
страницы редактора не защищает отдельный HTTP-транспорт. Логи и снимки проекта
могут содержать секреты. Это анализ документации, не проверка реального доступа.

## Подготовка переноса

`prepare_multiagent_port.py` — вспомогательный инструмент для локальной копии
репозитория multiagent. По умолчанию только проверяет конфликты; `--apply`
копирует отслеживаемые компоненты и manual-only workflows рядом с существующими
файлами, без их перезаписи. При совпадении файла или символической ссылке
отказывается от записи. Проверен перенос во временную папку с реальными
файлами указанного commit: все оригинальные файлы сохранены без изменений,
общий MCP прошёл локальный smoke test. Это подготовка исходников, а не
развёртывание; экспериментальный подписанный транспорт описан в README моста,
он не интегрирован с прежним неподписанным протоколом.

Дальше необходимо получить фактические исходники существующего WebSocket-моста,
клиента и редакторского аддона, согласовать доверенную границу и реализовать
адаптер с сохранением старого контракта и независимыми тестовыми стендами. Затем
проверить Web, Windows, Fedora ARM64 и Android отдельно, в том числе сценарии
Play/Stop, игровые кадры, удаление, файлы и логи, без обращения тестов к
действующей шаре или изменения рабочего сервера. Обновление действующего
репозитория и развёртывание не производились.
